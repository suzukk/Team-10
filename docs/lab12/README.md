Branch: `lab12-ai`

## Юу хийсэн

1. Даалгавар: манай төслийн US-12 (бүртгэл үүсгэх) болон US-13 (утасны дугаар)-тай
   холбоотой, бүртгэлийн оролтыг шалгадаг `validateRegistration()` функц.
2. AI хэрэгсэл: **Claude Code** (VS Code өргөтгөл). Prompt бүрийг төслийн кодыг
   харахгүй байхаар **хоосон хавтаст** (`D:\lab12-prompts`), **тусдаа шинэ
   session**-д өгсөн. Ингэснээр AI зөвхөн prompt-оос мэдээлэл авсан.
3. Ерөнхий prompt ба дэлгэрэнгүй prompt-ын хариуг харьцуулсан.
4. Дэлгэрэнгүй prompt-ын кодыг **өөрчлөлтгүйгээр** репод оруулж commit хийсэн, дараа
   нь review хийж асуудлуудыг тестээр илрүүлж (улаан), зассан (ногоон).

## 2. Review

Шалгуур (Лекц 13): логик зөв үү, аюулгүй юу, стилд нийцэж байна уу.

**Автомат шалгалт (AI-ийн код өөрчлөлтгүй үед):** `tsc --noEmit` алдаагүй,
`npx eslint .` (strictTypeChecked) алдаагүй, AI-ийн 15 тест бүгд давсан. Өөрөөр
хэлбэл автомат хэрэгсэл асуудал олоогүй — доорх асуудлуудыг кодыг гараар уншиж,
сэжигтэй тохиолдлыг туршиж олсон.

| № | Ангилал | Асуудал | Баталгаа | Засвар |
|---|---|---|---|---|
| 1 | Логик / Монгол хэрэглэгч | Том, жижиг үсгийг `/[A-Z]/`, `/[a-z]/`-ээр шалгадаг тул **кирилл үсгийг тоолдоггүй**. `Нууцүг2025` нууц үг "том үсэг алга, жижиг үсэг алга" гэж татгалзагдана. | Тест нэмэхэд улаан | `/\p{Lu}/u`, `/\p{Ll}/u` |
| 2 | Аюулгүй байдал / өгөгдлийн чанар | `trim()` нь хяналтын (`\u0000`, `\u0007`) болон zero-width (`\u200B`) тэмдэгтийг арилгадаггүй. **Зөвхөн үл харагдах тэмдэгтээс бүрдсэн нэр** зөв гэж хүлээн авагдана → хоосон харагдах хэрэглэгч, log/дэлгэц эвдрэх. | 3 тохиолдол улаан | `/[\p{Cc}\p{Cf}]/u` агуулсан нэрийг татгалзана |
| 3 | Логик / тууштай байдал | Нэрийн уртыг тэмдэгтээр (code point), харин **нууц үгийн уртыг UTF-16 нэгжээр** тоолдог. `Ab1😀😀😀` (6 тэмдэгт) нь 8-аас богино боловч зөвшөөрөгдөнө. | Тест нэмэхэд улаан | `Array.from(password).length`, хэт урт оролтод массив үүсгэхгүй хамгаалалттай |
| 4 | Тестийн чанар | ReDoS тест `elapsedMs < 200` гэж хатуу хугацаа шаарддаг — удаан CI машин дээр **санамсаргүй унах (flaky)** эрсдэлтэй. | Шинжилгээгээр | Хязгаарыг 1000 мс болгосон: шугаман regex хэдэн мс, catastrophic backtracking секунд, минут болдог тул ялгаа тод хэвээр |

**Асуудал биш гэж үзсэн зүйл:** `<script>` гэсэн нэр зөвшөөрөгдөж байгаа. Энэ нь
validation-ийн биш, харин нэрийг дэлгэцэнд гаргахдаа escape хийх (output encoding)
давхаргын үүрэг тул validation-д хориглохгүй.

**Нээлттэй үлдсэн зүйл:** AI өөрөө анхааруулсанчлан имэйлийн `@`-ийн өмнөх хэсэг 1–2
тэмдэгт (`a@mail.mn`) бол нууц үгэнд тэр үсэг орох бүрт татгалзана. Энэ нь бидний
өгсөн шаардлагыг яг мөрдсөн үр дүн тул шаардлагыг багаараа хэлэлцэж шийднэ.

## Тайланд оруулах тайлбар

Бүртгэлийн оролт шалгах `validateRegistration()` функцийг Claude Code-оор бичүүлж,
ерөнхий болон дэлгэрэнгүй хоёр prompt-ыг төслийн кодгүй хоосон хавтаст, тусдаа
session-д өгч харьцуулсан. Ерөнхий prompt-д AI JavaScript дээр, манай загварт
байхгүй `username`, `birthDate` зэрэг талбартай, монгол нэрийг татгалздаг код
гаргасан бол дэлгэрэнгүй prompt-д TypeScript дээр шаардлагыг бүрэн хангасан,
аюулгүй байдлыг тусгасан код болон 8 тест гаргасан. AI-ийн кодыг өөрчлөлтгүйгээр
commit хийгээд review хийхэд TypeScript, ESLint, тест бүгд алдаагүй байсан ч кодыг
уншиж туршихад кирилл үсгийг нууц үгэнд тоолдоггүй, үл харагдах тэмдэгтээс
бүрдсэн нэрийг зөвшөөрдөг, нууц үгийн уртыг буруу нэгжээр тоолдог гэсэн 3 асуудал,
мөн хугацаанаас хамааралтай flaky тест олдсон. Асуудал бүрийг эхлээд унах тестээр
баталгаажуулж, дараа нь засаж бүх тестийг ногоон болгосон. Энэ лабаас автомат
шалгалт давсан ч AI-ийн код манай хэрэглэгчийн онцлогт (монгол хэл) таарахгүй
байж болох тул хүний review зайлшгүй гэдгийг ойлгосон.
